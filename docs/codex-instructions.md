# Codex Instructions

이 문서는 Codex가 `ai` 폴더에서 작업할 때 지켜야 할 규칙입니다.

## 기본 원칙

- 기존 파일은 삭제하지 않습니다.
- 기존 프로젝트의 실행 경로를 바꾸는 대규모 이동은 하지 않습니다.
- 파일 이동이 필요하면 먼저 `docs/project-index.md`에 이동 제안으로 기록합니다.
- 실제 이동은 사용자가 승인한 뒤 별도 작업으로 진행합니다.
- 저장소 루트 구조는 변경하지 않고 `ai` 폴더 안에서만 작업합니다.
- 작업 전후로 `git status --short`를 확인합니다.

## 새 프로젝트 생성 규칙

새 프로젝트는 기본적으로 `projects/` 아래에 만듭니다.

```text
projects/project-name/
├─ README.md
├─ docs/
├─ notebooks/
├─ src/
├─ data/
├─ outputs/
└─ requirements.txt
```

단기 실험이나 한두 개의 노트북은 `experiments/` 아래에 둡니다.

## 문서화 규칙

프로젝트를 추가하거나 구조를 바꾸면 다음 문서를 갱신합니다.

- `README.md`
- `docs/project-index.md`
- `docs/roadmap.md`

프로젝트 README에는 최소한 아래 내용을 포함합니다.

- 목적
- 주요 파일
- 실행 방법
- 데이터 출처 또는 데이터 위치
- 현재 상태

## 데이터와 산출물 규칙

- 원본 데이터는 가능하면 `data/raw/`에 둡니다.
- 전처리 데이터는 `data/processed/`에 둡니다.
- 모델 파일, 결과 이미지, 리포트는 `outputs/` 또는 `reports/`에 둡니다.
- 대용량 파일은 커밋 전에 Git LFS 또는 외부 저장소 사용 여부를 확인합니다.

## 정리 후보

아래 항목은 자동 삭제하지 않습니다. 필요하면 별도 승인 후 정리합니다.

- `.ipynb_checkpoints/`
- `__pycache__/`
- `.pyc`
- 중복 노트북
- 임시 결과 파일
- 대용량 모델 파일

## 작업 방식

1. 먼저 현재 구조를 읽습니다.
2. 변경 범위를 문서 또는 작은 폴더 추가로 제한합니다.
3. 실행 코드의 import, 파일 경로, 데이터 경로는 건드리지 않습니다.
4. 변경 후 추가/수정된 파일 목록을 요약합니다.
